# Case Library：搜索排序异常排查

本文档记录搜索/列表排序异常排查中的常见 Case。所有内容均为脱敏后的通用示例，不包含任何真实公司系统、数据库表名、接口、产品 ID 或业务数据。

## Case001：对象基础状态异常

### 典型表现

- 对象在搜索或列表页排名明显下降
- 曝光突然减少
- 业务方反馈“之前能搜到，现在搜不到”
- 对象在某些条件下无法展示

### 排查方向

- 对象是否上线
- 对象是否可售或可展示
- 对象是否处于下架、暂停、过期等状态
- 对象是否命中限制规则
- 对象是否缺少必要基础信息

### 需要的证据

- 对象状态查询结果
- 上下线状态
- 可展示状态
- 基础信息完整性
- 最近状态变更记录

### 建议处理

如果确认对象状态异常，应先恢复对象基础状态，再观察搜索/列表曝光是否恢复。

---

## Case002：有效供给不足或库存异常

### 典型表现

- 搜索结果中对象排序下降
- 曝光减少但对象本身未下线
- 某些城市、类目、时间段下表现异常
- 用户能看到对象，但排序靠后

### 排查方向

- 是否存在有效供给
- 是否有库存或可服务能力
- 是否受地域、时间、类目限制
- 是否存在供给不足导致竞争力下降

### 需要的证据

- 供给状态
- 库存或可服务能力
- 地域或时间限制
- 同类对象对比数据

### 建议处理

如果有效供给不足，需要补齐供给、修复库存或调整服务范围，再观察排序变化。

---

## Case003：召回缺失或过滤规则命中

### 典型表现

- 对象在搜索结果中完全不可见
- 曝光接近 0
- 业务方反馈“搜不到”
- 对象只在部分查询词或筛选条件下消失

### 排查方向

- 对象是否进入候选集合
- 是否命中召回过滤规则
- 查询词、类目、地域等条件是否匹配
- 是否存在标签、属性或基础信息缺失

### 需要的证据

- 召回查询结果
- 过滤原因
- 查询条件匹配情况
- 对象标签或属性信息

### 建议处理

如果确认召回缺失，应优先修复基础标签、类目、属性或过滤规则，再进行排序层面的排查。

---

## Case004：排序因子下降

### 典型表现

- 对象仍能被搜索到，但排名下降
- 曝光下降但并非完全消失
- 点击、转化或质量表现下降
- 同类对象竞争中排名变差

### 排查方向

- 质量分是否下降
- 点击率、转化率是否下降
- 用户反馈是否变差
- 供给能力是否下降
- 竞争对象是否增强

### 需要的证据

- 排序因子变化
- 点击、转化、曝光指标
- 同类对象对比
- 用户反馈或质量指标

### 建议处理

如果排序因子下降，应定位下降因子，并从内容质量、供给能力、转化效率等方向优化。

---

## Case005：实验或策略调整影响

### 典型表现

- 排名或曝光在某个时间点后明显变化
- 多个对象同时出现类似波动
- 异常与策略发布时间接近
- 指标变化集中在部分流量或部分用户群体

### 排查方向

- 是否存在实验切流
- 是否存在排序策略调整
- 是否存在运营规则变更
- 是否影响特定分层、类目、地域或流量入口

### 需要的证据

- 策略变更记录
- 实验信息
- 流量分层变化
- 变更前后指标对比

### 建议处理

如果确认与实验或策略调整相关，应联系策略负责人进一步确认影响范围，并判断是否需要回滚、调参或继续观察。

---

## Case006：短期流量波动

### 典型表现

- 曝光或排名短期下降
- 没有明显状态异常
- 没有明确召回或排序因子异常
- 指标在历史上也存在类似波动

### 排查方向

- 是否为自然波动
- 是否受到大盘流量影响
- 是否只持续较短时间
- 是否影响范围较小

### 需要的证据

- 历史趋势
- 大盘流量变化
- 同类对象对比
- 多日连续观察结果

### 建议处理

如果判断为短期波动，建议继续观察，并设置监控阈值。如果波动持续扩大，再升级人工排查。

---

## Case 匹配原则

- 一个问题可能同时命中多个 Case
- 优先判断基础状态和召回问题，再判断排序因子
- 排序下降不一定代表排序系统异常
- 曝光下降需要结合召回、排序、供给和大盘流量共同判断
- 没有数据证据时，不应直接下结论

## 输出要求

Agent 在输出报告时，应说明：

1. 命中的 Case
2. 支撑该 Case 的证据
3. 当前无法确认的信息
4. 建议下一步操作
5. 是否需要人工升级
