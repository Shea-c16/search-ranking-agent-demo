# Agent 工作流说明

本文档说明搜索排序异常排查 Agent 的标准工作流程。该流程为脱敏后的通用设计，不依赖任何真实公司系统或内部数据。

## 1. 输入工单

Agent 接收用户提交的自然语言工单，例如：

> 对象 A 最近一周在搜索结果页的排名明显下降，曝光也比之前少很多，请帮忙排查原因。

输入中可能包含：

- 对象 ID
- 业务场景
- 问题描述
- 异常时间范围
- 异常指标
- 用户或业务方的补充说明

如果缺少关键信息，Agent 不应直接给出结论，而是先提示需要补充的信息。

## 2. 范围检查

Agent 首先判断该问题是否属于“搜索/列表排序异常”范围。

可处理的问题包括：

- 搜索结果页排名下降
- 列表页曝光异常
- 流量突然下降
- 召回缺失
- 排序因子异常
- 策略变更导致的排序波动

不可处理的问题包括：

- 与搜索/列表排序无关的问题
- 纯客服咨询
- 支付、账户、权限类问题
- 缺少对象 ID 且无法继续排查的问题

如果不在处理范围内，Agent 输出范围检查说明，并停止排查。

## 3. 信息提取

Agent 从工单中提取排查所需字段：

| 字段 | 说明 |
|---|---|
| 对象 ID | 被反馈排序异常的商品、内容、服务或其他业务对象 |
| 业务场景 | 搜索页、列表页、推荐页等 |
| 问题类型 | 排名下降、曝光下降、召回缺失、流量波动等 |
| 时间范围 | 问题发生的日期或周期 |
| 异常指标 | 曝光、点击、转化、订单、排名等 |
| 补充说明 | 用户或业务方提供的其他线索 |

## 4. 排查路径规划

Agent 根据问题类型规划排查路径，常见方向包括：

### 4.1 对象基础状态

检查对象是否处于正常状态，例如：

- 是否上线
- 是否可售或可展示
- 是否有有效库存或供给
- 是否被运营规则限制
- 是否命中风控或过滤规则

### 4.2 召回情况

检查对象是否进入候选集合，例如：

- 是否能被搜索召回
- 是否被过滤规则排除
- 是否满足查询条件
- 是否存在类目、地域、时间等限制

### 4.3 排序因子

检查影响排序的关键因子，例如：

- 质量分
- 供给能力
- 用户反馈
- 点击表现
- 转化表现
- 历史成交或互动表现

### 4.4 流量指标

检查核心指标是否异常，例如：

- 曝光
- 点击
- 转化
- 订单
- 排名位置
- 流量入口占比

### 4.5 策略或实验影响

检查是否存在策略变更，例如：

- 排序规则调整
- 实验流量切换
- 分层策略变化
- 运营规则变化
- 推荐或搜索策略更新

## 5. 工具调用

如果配置了数据查询工具，Agent 应优先调用工具获取证据。

工具调用原则：

- 先查数据，再给结论
- 查询结果必须进入证据链
- 工具失败时说明失败原因
- 不编造任何查询结果
- 不输出真实系统名、表名、接口或密钥

在本 Demo 中，工具调用通过 `mock_data_query` 表示，仅用于说明 MCP / Tool 的设计方式。

## 6. Case 匹配

Agent 根据证据匹配常见 Case：

| Case | 含义 |
|---|---|
| Case001 | 对象基础状态异常 |
| Case002 | 有效供给不足或库存异常 |
| Case003 | 召回缺失或过滤规则命中 |
| Case004 | 排序因子下降 |
| Case005 | 实验或策略调整导致流量变化 |
| Case006 | 短期流量波动，需继续观察 |

一个工单可能同时命中多个 Case，Agent 应并列说明，不应只给单一原因。

## 7. 报告生成

Agent 最终输出《搜索排序异常排查报告》，建议结构如下：

```text
1. 问题摘要
2. 范围检查
3. 已提取信息
4. 排查进度
5. 证据链
6. 可能原因
7. 建议操作
8. 对业务方的答复草稿
9. 是否需要升级人工排查
